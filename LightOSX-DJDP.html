Queue / playlist
Library

Each clip presses one of your DJ pads for its length. Drag a clip to move it (or to another lane), drag its right edge to resize, double-tap an empty lane to add one. Click the ruler or waveform to jump. Space = play/pause, ←/→ = seek, , and . = previous/next timeline. Timelines are saved in your settings file. The desktop app remembers where each song is on disk and opens it again by itself; in a browser use Relink folder once after a reload.

MIDI control

Map any button, slider, fader, dropdown or pad to a MIDI note or CC. Press Learn mode, click a control anywhere in the app (switch tabs freely), then move a knob or press a key on your controller. Esc leaves learn mode. Notes act as buttons, CCs work as faders or buttons (127 = pressed). To map a pad's Hold/Latch switch instead of the pad itself, turn on ⇄ Hold/Latch on the DJ Pads tab first (or hold Shift), then click the pad while learning.

DMX interfaces & universes

Add one row per device and connect. DMX interfaces get a universe (1–8); Bluetooth and PC RGB devices follow a fixture you link to them. Several can run at once, and they reconnect by themselves.

How many universes the universe lists, the DMX map and the Stage offer (1 to 8). Fixtures and interfaces that already use a higher universe keep it.

Interfaces reconnect by themselves if they drop or are unplugged, and again when the app starts. If a USB interface keeps dropping: plug it straight into the PC (no hub), use a short good cable, turn off Windows "USB selective suspend", and try a different refresh rate. Open DMX interfaces start at 40 Hz; lights can respond differently at different rates, so if a fixture misbehaves, try a lower one such as 14 or 30.

Advanced: choose protocol manually / Art-Net bridge

Art-Net / eDMX: browsers cannot send UDP, so a tiny helper relays frames to the network (over a WebSocket, which is faster and kinder to Wi-Fi than one HTTP request per frame; older helper files keep working over HTTP). or and run python3 bridge.py (Python 3) or node bridge.js (Node.js). To drive lights from a phone or tablet, run it on a PC or Raspberry Pi as python3 bridge.py 9099 0.0.0.0 and enter http://PC-address:9099 in the row.

Home Assistant & network control

This works in the desktop app only.

Lets Home Assistant (or any program on your network) press pads, black out, start or stop the chase and send a scene. It is off until you switch it on. Only programs that know the secret key below are accepted.

Paste the YAML into Home Assistant's configuration.yaml, restart it, and your pads appear as switches. Address examples: http://PC-IP:PORT/api/status, /api/pad/white/latch, /api/blackout/on, /api/chase/start, /api/master/60, POST /api/scene with {"prompt":"slow blue fade"}. Pad actions: on (press), off (release) and latch (flip it on or off, like a Latch pad; the older word toggle still works). Send the key as Authorization: Bearer KEY.

AI scene generator (local model)

Local models work in the desktop app only (a browser cannot reach a program on your computer).

Run any model you like in a local program (Ollama, LM Studio, llama.cpp server …) and LightOSX asks it to design the scene. Any size works: bigger models follow long prompts better but answer slower. Nothing leaves your computer.

Tip: with Ollama run ollama pull gemma3:12b once, then press Find models. If the model is not recognised or answers badly, the built-in engine is used instead.
